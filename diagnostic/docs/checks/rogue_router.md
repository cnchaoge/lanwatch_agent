# Check 1 — 私接小路由（Rogue Router）

> 状态：Draft v0.1（待超哥 review）
> 用途：MVP 前的 SOP 细化，**伪代码看 `checks/rogue_router_pseudo.py`**
> 最后更新：2026-09-24

---

## 一、为什么这一类最难

私接小路由是 4 类问题里**频次最高、误报代价最大、SOP 综合度最高**的：

- **频次**：员工自带家用路由接公司网，几乎每个公司都有
- **误报代价**：说"有人私接路由"结果只是合法的双 NAT 冗余 → 客户脸黑，超哥信誉丢
- **综合度**：要同时看 ARP / DHCP / 厂商 OUI / MAC 时间稳定性，单一信号不够准

所以这一类必须**多信号交叉验证 + 置信度分级**。

---

## 二、目标 / 输入 / 输出

| 项 | 内容 |
|----|------|
| **目标** | 判定内网是否存在员工私接的家用小路由 |
| **输入** | 本机主接口、ARP 表、主动扫描结果、DHCP 服务器列表、网关 MAC 时间序列 |
| **输出** | `verdict` (normal/warning/critical) + `confidence` (low/medium/high) + `evidence[]`（可呈现给客户的证据） |
| **不做什么** | 不试图定位具体是谁接的（仅指给客户看"存在这个设备"），不尝试远程关掉它 |

---

## 三、4 个判断维度

### 维度 A — DHCP 服务器数量

**信号**：抓 DHCP Discover / Offer 包，看 Option 54（Server Identifier）有多少个不同值

| 数量 | 判定 |
|------|------|
| = 1 | 正常（v1 客户大概率是这样） |
| = 2 | **高度可疑**（主 DHCP + 私接路由的 DHCP） |
| >= 3 | 几乎确认（除非客户明确说"我们有意做的 DHCP relay/中继"） |

**置信度**：高（DHCP 包无法伪造）

### 维度 B — 声称是网关的 MAC 数量

**信号**：向本机默认网关 IP 发 ARP Request，记录响应 MAC；同时扫整个子网，看哪些 MAC 在 gratuitous ARP 中声称自己是网关

| 数量 | 判定 |
|------|------|
| = 1 | 正常 |
| = 2 | **私接嫌疑大**（两个设备都"自称网关"，客户端会随机选） |
| >= 3 | 几乎确认（公司刻意多网关的极少；通常不会超过 2 个） |

**置信度**：高

### 维度 C — 未授权厂商的存活主机

**信号**：扫描整个 /24 子网（或 /22 等客户实际掩码），对每个响应 ARP 的 MAC 查 OUI 前缀

**白名单**（主流企业级网络设备厂商）：

```
Cisco      00:00:0C, 00:1A:A1, 00:1B:0D, 00:1D:A1, 00:22:55, ...
Huawei     00:E0:FC, 00:25:9E, 00:F8:1C, 04:BD:70, ...
Ruijie     00:D0:F8, 58:69:6C, ...
H3C        00:0F:E2, ...
Aruba      00:1A:2E, ...
Ubiquiti   24:5A:4C, 78:8A:20, ...
Mikrotik   00:0C:42, ...
Dell       00:14:22, ...
HP/HPE     00:08:02, ...
```

**黑名单参考**（家用消费级路由厂商，**不能单独作为判定依据**）：

```
TP-Link（部分型号）   14:CC:20, ...
Netgear        00:09:5B, ...
Tenda          C8:3A:35, ...
Mercury（水星） 00:1D:0F, ...
Fast（迅捷）    90:FB:A6, ...
Xiaomi         28:6C:07, 64:09:80, ...
360            BC:75:36, ...
```

> **重要**：黑名单 MAC 数量多 ≠ 私接路由。可能是合法 IoT / 员工手机 / 笔记本网卡。**只能作为辅助信号**。

| 黑名单 MAC 数量 | 判定 |
|----------------|------|
| < 5 | 正常（员工手机、IoT 设备） |
| 5-10 | 可疑但不报警 |
| >= 10 | 仅作为 WARNING 增强信号 |

**置信度**：低（OUI 不可靠，同厂商产品线混杂）

### 维度 D — 网关 MAC 时间稳定性

**信号**：连续采样 10 秒网关 IP 的 ARP 响应，看 MAC 是否变化

| 表现 | 判定 |
|------|------|
| 10 秒内 MAC 不变 | 正常 |
| 10 秒内 MAC 变了 >= 2 次 | **ARP 欺骗或主备切换**——私接路由经常伴随 ARP 欺骗 |

**置信度**：中

## 四、综合判定决策树

```
            ┌─────────────────────────────────────┐
            │  4 个维度的原始结果                  │
            │  A: DHCP 服务器数                   │
            │  B: 声称网关 MAC 数                 │
            │  C: 未授权厂商数量                  │
            │  D: 网关 MAC 漂移                   │
            └────────────────┬────────────────────┘
                             │
                             ▼
            ┌────────────────────────────────────┐
            │  A >= 2  AND  B >= 2 ?              │
            │  （DHCP + 网关双确认）              │
            └────────┬───────────────────┬───────┘
                     │ YES               │ NO
                     ▼                   ▼
            ┌─────────────────┐    ┌────────────────────────────┐
            │ CRITICAL        │    │  A >= 2 OR B >= 2 ?        │
            │ confidence=high │    │  （单信号确认）            │
            │ summary="强证据  │    └──────┬───────────────┬─────┘"
            │ 双信号确认私接" │           │ YES           │ NO
            └─────────────────┘           ▼               ▼
                                  ┌──────────────┐  ┌──────────────────────┐
                                  │ WARNING      │  │  C >= 10 OR D 漂移?   │
                                  │ confidence=  │  │  （弱信号）            │
                                  │ medium       │  └────┬────────────┬────┘
                                  │ summary="单  │       │ YES        │ NO
                                  │ 信号告警"    │       ▼            ▼
                                  └──────────────┘  ┌──────────┐  ┌─────────┐
                                                     │ WARNING  │  │ NORMAL  │
                                                     │ low conf │  │         │
                                                     └──────────┘  └─────────┘
```

### 判定阈值表（建议）

| 维度 | NORMAL | WARNING | CRITICAL |
|------|--------|---------|----------|
| A: DHCP 服务器数 | = 1 | = 2 | >= 3 |
| B: 声称网关 MAC 数 | = 1 | = 2 | >= 3 |
| C: 黑名单厂商数 | < 5 | 5-9 | >= 10 |
| D: 10s 内网关 MAC 变化次数 | 0 | 1 | >= 2 |

## 五、误报场景与对策

| 误报场景 | 特征 | 对策 |
|----------|------|------|
| **合法双 ISP 冗余** | A=2、B=2，但客户明确"我们有 2 条外线" | 报告里附**提示语**让超哥现场问"你们有几个外网出口？"——只要客户答 2 个，自动降级为 NORMAL |
| **DHCP Relay 中继** | A=2，但 Offer 包源 IP 是同一台 DHCP 服务器（IP Helper） | 检测 DHCP Offer 源 IP 是否都在核心交换机所在 VLAN——是则降级 |
| **测试环境 / 会议室临时路由** | 异常设备数量少，且都在某个 VLAN | 报告里标"集中在 VLAN X"，让超哥问客户"这是不是测试网段？" |
| **公司刻意部署的二级路由**（如部门独立网关） | B=2，但都是 Cisco/Huawei 企业级 | 维度 C 不命中 → 不会升级为 WARNING |

> **核心设计哲学**：宁可漏报不要误报。**漏报**下次还能补；**误报**会让客户不信超哥。

---

## 六、漏报场景与对策

| 漏报场景 | 原因 | 对策（v2.0 再考虑） |
|----------|------|---------------------|
| 私接路由**关掉了 DHCP**（手填 IP） | 维度 A 检测不到 | 维度 B + 维度 C 仍可能命中；v2.0 可加"非 DHCP 池的活跃 IP 探测" |
| 私接路由**接在会议室网线**，不在本机同 VLAN | ARP 扫描不到 | 报告里提示"建议在每个 VLAN 入口都跑一次" |
| 私接路由**伪装成网关 IP**（IP 冲突） | 维度 B 看到的是同一个 IP，但 MAC 在变 | 维度 D 会命中（MAC 漂移） |

## 八、待超哥拍板的问题

### Q1: DHCP 服务器白名单要不要做？

客户可能是 DHCP relay（中继）模式，主 DHCP 在核心交换机，AP/二层交换机会转发 Discover 但不响应 Option 54——这种情况 Option 54 还是只有 1 个（来自核心交换机）。

- **建议**：v1 不做白名单，2 个就报 WARNING，让超哥现场问"你们有几个 DHCP"
- **替代方案**：v2 加"DHCP relay 模式识别"——看 Offer 包的源 MAC 是否是同一台

### Q2: 扫描 /24 子网够吗？

大公司可能是 /22 甚至 /16。/24 主动 ARP 扫描需要 30-60 秒，/22 需要几分钟。

- **建议**：v1 默认扫 /24，加 `--full-subnet` 选项扫 /22，超时 120s 强制结束
- **v2 考虑**：从路由器 SNMP 学真实子网掩码（需要 router 凭据）

### Q3: 报告要不要直接给客户看证据（带 MAC 地址）？

- **支持**：最直观，客户能看到具体谁搞事
- **反对**：MAC 暴露给非技术人员，可能引发隐私争议（GDPR 风格）

- **建议**：默认给，**但加一句免责声明**："以下 MAC 地址仅供现场工程师参考，不写入客户可下载的报告 PDF"

### Q4: 维度 D（MAC 时间稳定性）放在 rogue_router 还是 arp_spoof 里？

- **当前方案**：rogue_router 里（因为私接路由常伴随 ARP 抢答）
- **替代方案**：arp_spoof 里（更专业）

- **建议**：rogue_router 里放"硬指标"（A/B/C），arp_spoof 里放"软指标"（D/时间序列）——避免重复
